# 总信息来源清单（sources.md）

> 这是项目的**数据基础**。抓取流程：**先确定渠道清单 → 再按清单抓取**。
> 每条渠道标注：观察链层级、对应观测指标、更新频率、状态。状态含义：LIVE=自动可用，STALE=需要人工核对，MANUAL=人工录入。

## 观测链与观测指标的对应关系

| 观察链层 | 观测内容 | 对应观测指标 |
|---|---|---|
| 认知层（模型/agent） | 新模型发布、能力跃迁 | agent 自主完成率 |
| 执行层（工具） | 工具采用、任务外包 | 单位任务成本 |
| 物理载体层（机器人/产线） | 出货量、部署、产能 | 物理产出增量 |

## 混合信源结构原则

- **行为数据**（LMArena/GitHub/Trends）定趋势，防空谈
- **一线实操者**（cocoloop/即刻/知乎）定细节，抓变化
- **生态系统交叉信号**（SEC 财报、Anthropic 指数）定实证，防幻觉
- **聚合器去噪**（TrendRadar/新闻）定广角，补盲区
- **中文层**定渗透速度，英文层定前沿上限

## 每期更新的最小工作流（阶段 3 目标）

1. **AI 自动**：扫描 LIVE 源 → 生成候选信号 → 打上观察链层/类型标签（转移/释放/新增）
2. **AI 初筛**：按三问筛选器剔除"转移"，标出候选"新增"
3. **人审**：确认"新增"信号，补充来源链接与证据
4. **写入** `data/signals.json`，更新状态与时间戳

> 新渠道如何加入？遵循 ai-news-radar"伯乐 Skill"模式：先验证信源质量 → 录入本清单 → 标状态 → 纳入抓取。
