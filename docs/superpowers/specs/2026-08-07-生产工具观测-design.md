# AI × 生产工具观测（生产工具雷达）design

> 日期：2026-08-07
> 状态：设计已确认（用户 2026-08-07 拍板）
> 定位：在现有"物理财富验证制"之上，新增一条**前置观测线**——盯住"AI × 具体生产工具"在商品页面与采购清单上的冒头与流转。
> 关联：《物理财富验证制.md》（四层判定 spec）、sources.md v2。

---

## 一、核心洞察（用户提出）

未来的新生财富，一定以 **"AI + 具体生产工具"** 的形式呈现。AI 叠加某个具体生产工具，会带来两个可观测变化：

1. **生产过程**：原来需要 5 人、10 人完成的工作 → 现在 1 人，甚至无人。
2. **生产产量**：原来的产量从 10 → 增长到 100 甚至更多。

因此**最直接的观测点 = 生产工具本身**。就像人们不断发明新的生产工具一样，AI 化工具会慢慢流转到整个市场里。**盯住商品页面和采购清单，就能看到这些新生产工具什么时候冒头、怎么流转。**

### 关键补充（用户二次洞察）：政府采购清单是更早的苗头

好的东西会**优先流向政府和富人阶层**。所以：

- **政府采购/央企采购清单**里出现 AI 化新生产工具 = **苗头指标**（官方确认 AI 被当正规生产工具），比普通商品页早一个周期。
- **普通商品页** = 普及指标（工具已流转到大众市场）。

**信号梯度**（从苗头到普及）：

```
政府采购/央企采购清单（最早苗头）
  → 众筹新品（Kickstarter/Indiegogo）
  → 垂直厂商新品（Bambu Lab/Unitree 等）
  → 1688/阿里国际站/Made-in-China（B2B 商品页）
  → Amazon/京东工业品（零售普及）
  → 下层市场流通
```

采购清单只作苗头指标，不计入主榜；苗头验证后才升级为 signals。

### 苗头限定（用户 2026-08-07 修正）：采购方必须是生产端

采购苗头**只看生产端企业**的采购：国有企业、私有企业、小企业均可——它一定是**企业生产部署或个人生产部署**。

**排除**：大学、科研机构、研究院的采购**不算**苗头。科研采购恰恰说明该工具"连个成型都没有"，是研发不是生产，不构成新增物理财富。

**判断规则**（看公告里的采购人，不看平台）：
- ✅ 生产端企业（中船/国家能源/中信戴卡/三棵树/蒙牛/美的等）采购 AI 生产装备 = 苗头
- ❌ 大学/研究所（如"某科技大学无序分拣机器人采购"）采购 = 研发采购，不入库

## 二、观测指标（贯穿全线的标尺）

每个被观测的生产工具，核心是 **双指标**（对应上面的两个变化）：

| 指标 | 字段 | 含义 |
|---|---|---|
| 人力变化 | `operators_before` / `operators_after` | 原来要几人 → 现在几人（1 或 0 是最强信号） |
| 产量变化 | `output_before` / `output_after` | 原来产量 → 现在产量（×10、×100 是最强信号） |

**AI 叠加的证据**：工具参数本身（"无人值守/自动换模/参数自学习/1 人可操作"）即 AI 叠加证据，不要求商品页标"AI"字样。

## 三、数据 schema：`data/tools.json`

新文件，`schema_version: 0.1.0`：

```json
{
  "_meta": {
    "schema_version": "0.1.0",
    "updated": "2026-08-07",
    "note": "生产工具观测：AI × 具体生产工具。双指标=人力↓/产量↑。状态：NEW新冒头/LIVE在售/STALE停更。渠道：kickstarter/b2b/vendor/retail/procurement。"
  },
  "tools": [
    {
      "id": "TOOL-2026-0001",
      "name": "桌面 AI 注塑机 XXX",
      "category": "注塑",                 // 3D打印/CNC/机器人/激光/注塑/切割/其他
      "price_tier": "personal",           // personal(万内) | small_biz(几十万) | enterprise(百万+)
      "metrics": {
        "operators_before": 5,
        "operators_after": 1,
        "output_before": 10,
        "output_after": 100
      },
      "ai_evidence": "自动换模/无人值守/参数自学习",
      "channel": "procurement",           // procurement | kickstarter | b2b | vendor | retail
      "source_url": "https://...",
      "status": "NEW",                    // NEW | LIVE | STALE
      "discovered_at": "2026-08-07",
      "last_updated": "2026-08-07"
    }
  ]
}
```

### price_tier（可及性分层，对应生产工具阶梯）

- `personal`：个人可负担（万元内）→ AI + 3D 打印三件套
- `small_biz`：小企业（几十万）→ 开源机器人二次开发层
- `enterprise`：大企业（百万+）→ 机器人/机床/自动化产线

## 四、苗头指标层：采购清单（新增来源）

| 来源 | 类型 | 状态 | 获取方式 |
|---|---|---|---|
| 中国政府采购网 + 央企采购平台 | 工业机器人/智能装备采购公告 | MANUAL/STALE | 官网/搜索 |
| 美国联邦采购 GSA Advantage / FedMall | 联邦采购目录 | MANUAL/STALE | 官网 |
| 上市公司/中标公告 | AI 生产装备采购金额与供应商 | MANUAL/STALE | 巨潮/交易所 |

**用法**：采购清单只作苗头（`status: NEW` 且 `channel: procurement`）。**入库前提：采购人为生产端企业**（国有/私有/小企业），大学与科研机构采购一律不入库（研发≠生产）。当采购清单中某工具被证实落地（产出数据披露）→ 升级为 signals `new_verified`。

---

## 五、核心流水线（工具观测是信号的前置层）

```
商品页面/采购清单(新工具冒头) → tools.json(NEW) → 人工确认 → LIVE(在售) → 被证实 → signals.json(new_verified)
```

- **工具层 = 更早的信号源**。商品页先出现"AI×生产工具"，然后才流转到市场、被企业采用、反映在财报里。
- **已证实路径**：工具 LIVE 后，出现实证（用户自报产能、厂商披露出货量、测评给出产量数据）→ 升级为 `new_verified` 信号进主榜。
- **待验证路径**：工具参数写着"1人操作/产量×10"但无实证 → 保持 NEW/LIVE，作为待验证池。
- 采购清单的 `procurement` 工具是苗头中的苗头，权重最高。

## 六、页面板块（替换现有静态阶梯）

现有"生产工具可及性阶梯"是写死的 3 行静态 HTML → **改为由 tools.json 驱动**，按 `price_tier` 分组展示：

- **个人层**（万内）：3D 打印、桌面注塑、激光切割、小型 CNC
- **二次开发层**（几十万）：开源机器人、工业级桌面设备
- **大企业层**（百万+）：机器人产线、工业 CNC、注塑机

每条卡片展示：名称、类目、状态点（NEW/LIVE/STALE）、**人力↓ 产量↑ 双指标**、价格分层、来源链接。苗头来源（procurement）工具用特殊标记。

---

## 七、采集与维护工作流

1. **AI 扫描**（每期）：扫 Kickstarter/Indiegogo 上新 + 厂商新品页（Bambu Lab/Unitree 等）+ 1688/阿里国际站新品 + 采购公告 → 发现候选，写入 `status: NEW`
2. **人工确认**（用户/AI 协助）：核实商品页参数、填 metrics、定 price_tier → `LIVE`
3. **回访**：在售工具每期核对参数与实证；停更/停产 → `STALE`
4. **升级信号**：出现实证的工具 → 同步进 `signals.json` 为 `new_verified`，两处互链

## 八、与现有数据的关系

- `tools.json` 新增独立文件；`sources.md` 补"生产工具观测 + 采购清单"小节

## 九、范围与 YAGNI

- **不做**：不自动抓商品页价格（反爬严重、维护成本高）；采购清单仅人工/半自动录入，不作自动采集。
- **第一版**：tools.json schema + 页面数据驱动板块 + 首批手工录入工具（含至少 1 个 procurement 苗头示例）。
- **后续可选**：Kickstarter API 半自动扫描、中标公告检索自动化。
