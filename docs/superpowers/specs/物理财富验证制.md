# 物理财富验证制（最终标准）spec

> 状态：已确认（用户 2026-08-07 拍板）
> 配套：《生产方式重塑信号清单》《sources.md v2》
> 本文是"唯一标准"的可执行版本，约束 `data/signals.json` schema 与页面展示。

---

## 一、核心定义：财富 = 物理财富（实体产出）

**唯一标准**：判断一条信号是否创造"新增财富"，最后一步永远是问——

> **这条信号是否变成更多实物被生产出来？**

- 服务 / 效率 / 软件必须**依托物理财富展开**才计入；脱离实物的纯数字增长视为"释放/前置"，不视为"新增"。
- 新产品必须是**实体**（能落地、可交付的物），纯虚拟产品不算新增物理财富。

**分界线（用户原话）**：服务/效率依赖物理财富 → 实体产出被证实 → 才算"新增"。

---

## 二、四层判定（signals.type）

每条信号最终归入四层之一，`type` 从原来的三分类扩展：

| type | 名称 | 判定 | 进主榜 |
|---|---|---|---|
| `transfer` | 转移 | 零和：卖课/信息差/转手差价，把旧蛋糕换个人吃 | 否（噪音样本反衬） |
| `release` | 释放 | 提效：同样投入更多产出，但资源尚未流向新实物产出 | 否（标注"通向哪个实物产出"） |
| `new_pending` | 新增·待验证 | 做出原本做不出的东西，但**实物产出尚未被证实**（有样品/原型/小批量，无确认证据） | 待验证区 |
| `new_verified` | 新增·已证实 | 实物产出**已被证实**（企业披露成本↓/产能↑/实物出货、有硬证据链接） | 主榜 |

**判定流程**：transfer/release → 不进主榜；new 再走一次"实物产出是否被证实"分叉：

```
信号 → 三问筛选（转移？释放？新增？）
         ├─ transfer → 噪音样本
         ├─ release → 标注"通向哪个实物产出"，未证实前留在释放
         └─ new → 实物产出被证实了吗？
                    ├─ 否 → new_pending（样品/原型/小批量，进待验证区）
                    └─ 是 → new_verified（企业披露/出货证据，进主榜）
```

## 三、生产工具可及性阶梯

谁有资格生产实物，按工具可及性分三层（用户判断 + 调研修正）：

| 层 | 工具 | 证据 | 结论 |
|---|---|---|---|
| **个人层** | AI（设计/营销） + 3D 打印（原型/样品） | Hi3D：AI 自动化 3D 打印最难步骤，个人无需 CAD 开实物生意；桌面 3D 打印机数百美元，工业 CNC 数十万美元 | **成立**：3D 打印是个人可及的生产工具，机床个人不可及 |
| **二次开发层** | 开源机器人（Unitree Go2/H1/B2/G1 SDK2 + ROS2） | 开源生态个人可改代码、可二次开发 | **成立**：个人可修改机器人，但暂无"个人用机器人做出可售实物"实证 → 划归待验证 |
| **大企业层** | 机器人 / 机床 / 自动化产线 | WEF 灯塔 224+ 家披露成本↓/产能↑硬数字；国家统计局工业机器人产量 | **成立**：规模化由大企业承担，官方可查证 |

**关键修正（调研补充）**：个人生产工具不是单一"3D 打印"，而是**三件套**——

> **AI（设计/营销）+ 3D 打印（原型/样品）+ 供应链代工（小批量量产）**

- 多数工厂 MOQ 1 万件，个人硬件靠供应链伙伴（如 Breeze 深圳代工从 1000 件起）。
- 例证：MemoTalk.ai（上海临港 OPC 社区，约 5 人团队 4 个月做出实体 AI 记忆硬件），靠供应链整合 + 工业设计，非个人独立制造。

## 四、signals schema：新增 `physical` 字段

每个 `new_pending` / `new_verified` 信号必须携带 `physical` 对象：

```json
{
  "id": "SIG-2026-0001",
  "type": "new_pending",               // 四层之一
  "physical": {
    "product": "实体产品名/形态（必填）",   // 必须指向一个"物"
    "verified": false,                  // 实物产出是否被证实
    "evidence": "样品/小批量/企业披露原文",
    "scale": "individual"               // individual | factory | scaled
  }
}
```

`scale` 取值：
- `individual`：个人/小团队实物产出（样品、小批量）
- `factory`：单厂/企业内部实物产出（产线落地、成本降幅）
- `scaled`：规模化扩散（多厂、全国产能、行业级）

## 五、个人起源监测线（"起源"如何被证实）

个人实物产出（哪怕一件样品）视为**起源**，对应"电力重塑第一家工厂"。监测线：

```
AI × 3D 打印（个人生产工具）→ 实物样品 → 供应链小批量 → 物理财富
        ↑                           ↑              ↑
    工具可及性证据            new_pending        new_verified
   （Hi3D/3D 打印成本）     （样品/原型）      （小批量出货/收入）
```

- 每个环节都要有证据，证据缺一环就停在当前层。
- 个人层信号重点是"个人用 AI 做出原本做不出的**物**"，不是做出 App/服务。

---

## 六、对现有数据的迁移要求

1. `data/signals.json`：schema_version 升为 `0.3.0`；`type` 中 `new` 拆为 `new_pending` / `new_verified`。
2. 现有 new 信号（SIG-0001/0002/0003）逐条重新判定：
   - 纯软件/服务且无实物产出 → 降为 `release` 或 `new_pending`（补 physical.product 指向的实物，若无法指向实物则降级）。
   - 能指向实物产出（如代运营无实物→release；若某条涉及实体商品生产则保留 new_pending）。
3. 所有 `new_*` 信号必须带 `physical` 字段，缺字段不发。
4. 页面展示：主榜只显示 `new_verified`；待验证区显示 `new_pending`；释放/转移不进主榜。
